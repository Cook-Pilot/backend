# F-12 장보기·냉장고 재료 기반 소진 레시피 추천

## 목표와 범위

사용자가 냉장고에 갖고 있는 재료를 이모티콘 수준으로 가볍게 담아두면, 그
재료를 실제로 쓰는 레시피를 소진 임박 순으로 홈 화면에 추천한다. 재료
보유 여부만 판단할 뿐 레시피나 개인 버전을 직접 수정하지 않는다.

이번 범위는 재료 담기·삭제와 추천 조회다. 장보기 리스트/구매 체크,
재고 자동 차감, 재료 마스터 데이터 정규화(동의어 통합 등)는 포함하지
않는다.

## 데이터 모델

별도 재료 마스터 테이블이 없어 `recipe_ingredients.name`과 동일한 한글
표기를 그대로 매칭 키로 쓴다.

- `pantry_ingredient_catalog`: 이모티콘 빠른 담기 UI용 재료 카탈로그.
  현재 8개 카탈로그 레시피에 실제 쓰이는 재료 23종을 사람이 curate했다
  (물은 소진 관리 대상이 아니라 제외). 재료별 기본 소진 기한
  (`default_shelf_life_days`)을 함께 둔다.
- `pantry_items`: 사용자가 담은 재료와 소진 예정일. `(user_id,
  ingredient_name)` UNIQUE — 같은 재료를 다시 담으면 새 배치를 쌓지 않고
  소진 예정일만 갱신한다.

## 매칭·정렬 정책

1. 사용자의 보유 재료 이름을 공백 제거·소문자 정규화해 비교 키로 쓴다
   (F-11 추천 엔진과 동일한 정규화 방식).
2. 활성 레시피의 재료 목록과 대조해 하나 이상 겹치는 레시피만 후보로
   삼는다.
3. 후보 레시피는 **가장 임박하게 상하는 매칭 재료의 소진 예정일** 기준
   오름차순으로 정렬한다. 동률이면 매칭된 재료 개수가 많은 쪽, 그다음
   레시피 제목 순으로 결정론적으로 정렬한다.
4. 최대 3건을 반환한다.

## API

- `GET /api/v1/pantry/ingredient-catalog` — 이모티콘·기본 소진 기한 포함
  카탈로그 목록
- `GET /api/v1/pantry/items` — 보유 재료 목록(소진 임박순, 잔여일 포함)
- `POST /api/v1/pantry/items` — 재료 담기. `useByDate`를 생략하면 카탈로그
  기본 소진 기한으로 오늘부터 계산해 채운다. 카탈로그에 없는 이름은
  400.
- `DELETE /api/v1/pantry/items/{itemId}` — 다 썼거나 버린 재료 제거
- `GET /api/v1/pantry/recipe-suggestions` — 소진 임박 우선 추천 레시피
  (최대 3건), 레시피별 매칭 재료·잔여일 포함

## DB 변경

`V10__add_pantry.sql`

- `pantry_ingredient_catalog`: 재료 23종 seed
- `pantry_items`: 사용자별 보유 재료(소진 예정일 포함)

## 검증

- 재료를 담으면 카탈로그 이모지와 함께 소진 임박순으로 조회됨
- 같은 재료를 다시 담으면 배치가 늘지 않고 소진 예정일만 갱신됨
- 카탈로그에 없는 재료는 담을 수 없음(400)
- 재료를 삭제하면 목록과 추천에서 사라짐
- 추천은 소진 임박 재료를 우선하고, 겹치는 재료가 없는 레시피는 제외함
- 다른 사용자의 재료가 내 추천에 영향을 주지 않음
