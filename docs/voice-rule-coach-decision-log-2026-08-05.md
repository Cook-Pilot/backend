# 조리 중 음성 룰베이스 코치(SafetyRuleCoach) 정밀도 결정·검증 로그

- 기록일: 2026-08-05 (Asia/Seoul)
- 상태: 수정 반영, 테스트 통과. 프론트와의 규칙 동기화 방식은 미결
- 구현 위치: [`SafetyRuleCoach.java`](../src/main/java/com/cookpilot/api/SafetyRuleCoach.java)
- 대응 프론트 구현: `frontend/lib/services/local_coach.dart`
- 관련 로그: `frontend/docs/voice-processing-decision-log-2026-08-04.md`

## 문제

`SafetyRuleCoach.fallbackAnswer`는 Gemini가 미설정이거나 호출에 실패했을 때 사용자에게 실제로 나가는
최후 응답 경로다. 이 경로가 한 글자 substring으로 매칭하고 있어 두 방향으로 모두 틀렸다.

**과잉 매칭** — 한국어는 교착어라 한 글자가 다른 단어의 조각으로 들어간다.

| 발화 | 매칭된 조각 | 잘못 나간 답변 |
|---|---|---|
| "파스타 면 얼마나 삶아" | `타` | "불을 즉시 줄이고 바닥을 긁지 마세요" |
| "타이머 얼마나 남았어" | `타` | 같음 |
| "리코타 치즈 넣어도 돼" | `타` | 같음 |
| "진짜 이거 맞아" | `짜` | "물을 한 스푼씩 추가해 간을 확인하세요" |
| "이번 주 요리 계획을 짜" | `짜` | 같음 |

**누락** — 정작 진짜 호소는 패턴에 없었다. `짜`/`짰`만 있고 `짠`이 없어 "소스가 너무 짠 것 같아"가 빠졌고,
`타`만 있고 `탄`/`탔`이 없어 "탄내가 나", "고기가 다 탔어", "겉이 까맣게 됐어"가 전부 빠졌다.

원인은 2026-07-30 프론트 커밋(`95d0e84`, "짠맛 오탐 판별 정교화")에서 `LocalCoach`만 고치고 같은 역할을
하는 백엔드를 함께 고치지 않아 두 구현이 갈라진 것이다.

## 결정

### 짠맛 — 프론트 `LocalCoach._isSaltyDescription` 규칙을 그대로 이식

맛/조리 맥락어(`간이`, `국물`, `양념`, `너무`, `조금` 등)와 AND로 묶고, `짜` 앞 음절이 `진`·`가`면 제외하며,
`계획을짜`류 관용구를 명시 배제한다. 두 구현이 이미 한 번 갈라졌으므로 규칙을 동일하게 맞추는 것을 우선했다.

### 탄 것 — 조각으로 나타날 수 없는 2음절 이상 형태만 사용

`눌어붙`, `탄내`, `타는냄새`, `타버`, `타고있`, `탔`, `까맣게`.

검토했으나 기각한 대안:

1. **프론트 규칙(`타고`, `눌어붙`)을 그대로 이식** — 기각. 프론트 쪽도 `탔어`·`탄내`를 못 잡는 같은 누락을
   갖고 있다. 이식하면 과잉 매칭만 없애고 누락은 그대로 남는다. 이쪽은 프론트를 백엔드에 맞추는 것이 맞다.
2. **`타는`을 추가** — 기각. "이거 파스타는데 어떡해"처럼 조사가 붙으면 `파스+타는`으로 다시 조각 충돌이 난다.
3. **짠맛과 같은 선행 음절 배제 방식을 `타`에도 적용** — 기각. `타이머`는 문장 첫머리라 선행 음절이 아예 없고,
   `파스타`는 선행이 `스`인데 `스`를 금지하면 정상 발화까지 막힌다. 선행 음절만으로는 분리가 불가능하다.
4. **형태소 분석기(KOMORAN/Okt) 도입** — 기각. 이 경로는 Gemini 실패 시의 최후 응답이라 의존성 없이 가볍고
   결과가 예측 가능해야 한다. fallback 하나 때문에 모델 로딩과 지연을 추가하지 않는다.

### 안전 규칙(`safetyAnswer`)은 건드리지 않음

`상한`이 "이거 이상한데"에, `속이빨`이 "속이 빨리"에 걸리는 오탐이 있다. 다만 이 경로의 오탐은 "맛보지 말고
버리세요", "중심 온도를 확인하세요" 같은 보수적 답변으로 귀결되어 안전한 방향으로 틀린다. 안전 규칙은
재현율을 정밀도보다 우선한다는 기존 설계를 유지한다.

## 검증

`SafetyRuleCoachTest`에 고정 말뭉치 회귀 테스트를 추가했다(기존 2개 → 25개).

- 수정 **전** 코드 기준: 25개 중 **13개 실패** (과잉 매칭 7, 누락 6)
- 수정 **후**: 25개 통과, 백엔드 전체 스위트 32개 통과

말뭉치는 프론트 `test/services/local_coach_test.dart`의 `진짜`/`가짜`/`계획을 짜` 케이스와 겹치도록 구성해
두 구현이 다시 갈라지면 양쪽 중 한쪽에서 드러나게 했다.

## 남은 것

- **프론트-백엔드 규칙 동기화 방식 미결.** 지금은 같은 판정을 Dart와 Java에 각각 구현하고 말뭉치만 겹쳐 놓은
  상태라 또 갈라질 수 있다. 공유 말뭉치를 문서 하나로 두고 양쪽 테스트가 그 문서를 읽게 하는 방안이 후속 과제다.
- 프론트 `LocalCoach`의 탄 것 패턴(`타고`)에도 같은 누락이 있다. 프론트 담당과 조율 후 반영 필요.
- 이번 범위 밖으로 남긴 백엔드 음성 경로 이슈 3건:
  - `/ai/feedback`만 `Idempotency-Key`를 쓰지 않아 재시도 시 Gemini 중복 호출·`ai_interactions` 중복 적재
  - 서버측 호출 가드 없음 (프론트 `voice_call_guard`에만 존재)
  - `GeminiCoach`가 모든 예외를 삼켜 fallback 원인(타임아웃/HTTP/파싱)을 구분할 수 없음
