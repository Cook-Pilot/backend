# 운영 레시피 카탈로그 정리

## 배경

2026-08-17 운영 DB를 읽기 전용으로 감사했을 때 다음 문제가 남아 있었다.

- 레시피 1,164건 중 공백을 제거한 제목이 같은 중복 그룹 13개(삭제 후보 14건)
- `L..A갈비구이` 제목 오탈자 1건
- `양파(20g)`처럼 수량이 `recipe_ingredients.name`에 들어가고 `amount`와 `unit`이 비어 있는 행 6,659건

중복 후보의 본문은 서로 완전히 같지 않아, 단계가 있는 레시피를 우선하고 재료 수가 많은 레시피를 그다음으로 선택했다. 동점이면 올바른 띄어쓰기와 설명이 더 충실한 행을 남겼다. 삭제 후보에는 즐겨찾기, 조리 리뷰, 개인 레시피 버전, 추천 피드백 참조가 모두 0건이었다.

## 안전 조치

변경 전 전체 PostgreSQL 덤프를 아래 위치에 별도 보관했다.

`s3://cookpilot-backup-167403240280/manual/cookpilot-pre-recipe-cleanup-20260817T044136Z.sql.gz`

정리 SQL은 [2026-08-17-recipe-catalog-cleanup.sql](../infra/maintenance/2026-08-17-recipe-catalog-cleanup.sql)에 있다. 운영 감사 시점의 레시피 수와 대상 UUID를 전제조건으로 확인하고, 모든 작업을 한 트랜잭션에서 실행한다. 대상 데이터가 달라졌거나 사용자 참조가 생겼으면 삭제 전에 실패한다.

## 수량 변환 정책

- 정수·소수와 단위: `양파(20g)` → `name=양파`, `amount=20`, `unit=g`
- 일반 분수: `양파(1/2개)` → `amount=0.5`, `unit=개`
- 유니코드 분수: `양파(½개)` → `amount=0.5`, `unit=개`
- 계량 약어: `Ts/T/tbsp`는 `큰술`, `ts/t/tsp`는 `작은술`
- `약간`, `적당량`, 빈 괄호는 이름에서 제거하고 수량을 비워 둔다. 현재 UI는 빈 수량을 `적당량`으로 표시한다.
- `소고기(불고기용)` 같은 설명 괄호는 수정하지 않는다.

`2~3개`처럼 상한과 하한이 있는 9건은 현재 단일 `NUMERIC amount` 스키마로 손실 없이 표현할 수 없어 원문을 유지한다. 임의로 평균값을 저장하면 조리 의미가 바뀌므로, 향후 범위 수량 스키마를 추가할 때 별도로 옮긴다.

## 실행 결과

같은 운영 DB에서 먼저 전체 트랜잭션을 `ROLLBACK`으로 실행해 검증한 뒤, 동일한 SQL을 `COMMIT`했다.

- 레시피: 1,164건 → 1,150건
- 중복 레시피 삭제: 14건(정규화한 제목 중복 그룹 13개 → 0개)
- 제목 교정: 8건
- 남겨 둔 레시피의 재료 정규화: 6,599건
- 숫자와 단위가 붙은 단순 괄호 수량: 0건
- 스키마 지원 전까지 원문을 보존한 범위 수량: 9건

커밋 후 DB 재조회와 `/api/v1/recipes` 응답을 각각 확인했다. API 목록은 1,150건이고 `LA 갈비구이`와 `가지볶음`은 각각 1건이다. 상세 API와 웹 화면에서는 첫 재료가 `LA갈비`, `200g`으로 분리되어 표시되며, 조리 단계 2곳의 `L.A 갈비` 표기도 `LA갈비`로 통일했다.
