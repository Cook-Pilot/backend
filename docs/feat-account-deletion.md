# feat/account-deletion — 계정 삭제 API (#79)

## 무엇을, 왜

개인정보처리방침 초안 v2.4 제9조("계정과 모든 개인정보를 한 번에 삭제")·제4조("탈퇴 시
후기와 첨부 사진은 본문과 사진 파일까지 함께 삭제, 익명 보존 없음")가 약속하는 기능이
아예 없었다. 삭제 API 도, 화면도 없고, 스키마(`post_cook_reviews.user_id ON DELETE SET NULL`)는
반대로 익명 잔존을 만든다. Google Play(계정 삭제 요건)·Apple 5.1.1(v) 모두 앱 내 삭제를
요구하므로 출시 차단급.

## 핵심 설계 결정

1. **삭제 순서: S3 사진 → DB 행(+탈퇴 기록) → 카카오 unlink.** 순서가 재시도 안전성을
   만든다. S3 실패 → 500, 계정 그대로 → 재호출. DB 실패 → 사진만 먼저 사라진 상태 → 재호출.
   반대(DB 먼저)면 실패 시점에 계정이 이미 없어 재호출이 404 로 막히고 사진이 영영 남는다.

2. **`post_cook_reviews.user_id` 를 `SET NULL` → `CASCADE`** (V22). "탈퇴해도 익명 통계로
   남긴다"는 결정을 한 적이 없고 방침 제4조는 반대를 약속한다. 익명화가 필요해지면 그때
   명시적 UPDATE 로 하는 게 맞다 — FK 기본 동작으로 몰래 하는 게 아니라.

3. **탈퇴 기록(tombstone) `account_deletions`** (V22). 방침 제8조 "백업 복원 시 탈퇴자
   정보가 되살아나지 않도록 재적용"은 무엇을 지웠는지 기록이 없으면 실행 불가능한 약속이다.
   내부 난수 UUID 만 남기므로(연결 고리는 전부 삭제됨) 그 자체는 개인을 식별하지 않는다.
   행 삭제와 **같은 트랜잭션**이어야 한다 — 기록만 남고 계정이 살아 있으면 복원 절차가
   멀쩡한 계정을 지운다. 재적용 절차는 `infra/README.md` 재해 복구 5번.
   한계: 서버 전체 소실 시 마지막 백업 이후의 탈퇴 기록은 함께 사라진다(노출 창 = 백업 주기).

4. **S3 는 접두사 일괄 삭제.** #74 부터 키가 `review-photos/{userId}/…` 라 리뷰 행을 읽지
   않고 ListObjectsV2 + DeleteObjects 로 지운다. 부분 실패(`deleted.hasErrors()`)도 500 으로
   올린다 — 일부만 지워진 채 성공하면 방침 위반이 조용히 잔존한다. #74 이전의 옛 공개 URL
   행은 키 역산이 불가능해 대상 밖(베타 데이터 정리 #52·#71 미결과 함께 판단).

5. **카카오 unlink 는 best-effort.** 카카오 개발자 정책이 탈퇴 시 unlink 를 요구하지만
   (admin key 경유 `POST /v1/user/unlink`), 카카오 장애가 우리 삭제를 막으면 방침 제9조를
   못 지킨다. 실패는 로그만 남기고 진행, 미해제 건은 로그로 수동 처리. `KAKAO_ADMIN_KEY`
   미설정이면 건너뛴다(로컬·CI). Google revoke 는 정책 요구가 아니라 하지 않는다(이슈 합의).

6. **트랜잭션 경계.** 외부 호출(S3·카카오)은 DB 트랜잭션 밖(AuthService 의 제공자 호출과
   같은 원칙 — 외부가 느리면 커넥션 풀이 마른다). 그래서 오케스트레이션(`AccountDeletionService`,
   무트랜잭션)과 행 삭제(`UserService.deleteAccount`, `@Transactional`)를 클래스로 나눴다 —
   같은 빈 내부 호출은 프록시를 타지 않아 self-invocation 으로는 트랜잭션이 안 걸린다.

7. **삭제 후 살아 있는 JWT.** 무상태 토큰(최대 14일)이지만 `getCurrentUser()` 가 DB 를
   조회하므로 `UserNotFoundException` → **404** 로 걸러진다(핸들러 기존 매핑 확인).
   같은 이유로 삭제 API 재호출도 404 = 멱등.

## API

| 메서드 | 경로 | 응답 |
| --- | --- | --- |
| `DELETE /api/v1/users/me` | 본인 세션 필수 | 204. 재호출 404 |

삭제 대상: users 행 + 후기(CASCADE, V22)·개인 버전·즐겨찾기·추천 반응(기존 CASCADE) +
S3 사진 객체 + 카카오 연결. 재가입은 `(provider, provider_user_id)` 유니크라 새 계정이 된다.

## 범위 밖 (이슈 체크리스트의 나머지)

- **프론트 설정 화면** (Cook-Pilot/frontend) — 확인 다이얼로그 + 로컬 세션·문서 디렉터리 정리
- **웹 삭제 요청 페이지** (Cook-Pilot/web) — Play 양식에 넣을 URL
- 옛 공개 URL 행의 사진 객체 정리(#52·#71 미결)

남지 않는지 + 탈퇴 기록이 남는지 ② 재호출·삭제된 세션의 개인화 API 가 404(500 아님)

공유하므로 건드리지 않고 익명 발급으로 격리했다.

탈퇴 → S3 접두사 객체 0개, 카카오 개발자 콘솔에서 연결 해제 확인.
