# feat/recipe-tag-import-backfill — 원문 분류를 태그 부여로 (V21)

## 무엇을 왜

`tags` 사전에 24행이 있는데 `recipe_tags` 는 **0행**이다. 태그 체계는 있지만 붙은 태그가 없어서
홈 화면의 카테고리(파티·안주·한식…)를 만들 수 없다. 프론트 개편(Cook-Pilot/frontend#63)에서
상단 카테고리 칩을 뺀 이유가 이것이다 — 눌러도 빈 화면이 나온다.

부여를 채우는 길은 둘이다. **원문에 답이 있는 축(음식형태·조리법)** 과 **없는 축(문화권·용도)**.
이 PR 은 앞의 둘을 채운다. LLM 으로 채우면 공짜로 얻을 수 있는 것을 틀릴 수 있는 것으로 바꾸는 셈이다.

## 원문이 이미 DB 안에 있다

임포터가 원문 분류를 버리지 않고 `recipes.description` 에 문자열로 남겨 뒀다.

```
월계수잎과 통후추 등을 사용해 …
조리방법: 굽기 | 요리종류: 반찬
1인분 310.8kcal · 탄수화물 9.4g · …
```

운영 1,150행 중 **1,142행**이 이 꼴이다. 나머지 8행은 Flyway 시드(라면·김치볶음밥 등)로 애초에
식약처 데이터가 아니다.

## 검토한 대안 — 왜 도구(#77)를 쓰지 않았나

`infra/maintenance/tools/extract_recipe_tags.py` 가 같은 일을 한다. 그 도구는 **원문 API 를 다시
받아 제목으로 맞춘다.** 두 가지 대가가 있다.

1. **제목은 유일하지 않다.** 겹치는 7종 14행은 축별로 값이 갈리면 판단 불가로 남는다.
   여기서는 각 행이 자기 분류를 들고 있어 **매칭이라는 단계 자체가 없다.**
2. **입력 두 개가 필요하다** — 원문 API 키(공공데이터포털)와 운영 DB 덤프(AWS CLI + SSM).
   지금 둘 다 없고, 그래서 이 작업이 멈춰 있었다. 마이그레이션은 배포로 적용되므로 둘 다 필요 없다.

**도구가 쓸모없다는 뜻은 아니다.** 원문에만 있고 DB 에 안 남은 값(문화권)이나 출처 번호
(V18 `source_ref`) 백필은 여전히 원문 대조가 필요하다.

## 실제 데이터로 검증한 결과

운영 API(`GET /api/v1/recipes`, #76 으로 게스트 공개)로 1,150행을 받아 임시 postgres 에 적재하고
**이 마이그레이션 파일을 그대로 실행했다.**

| 축 | 부여 |
| --- | --- |
| DISH | 반찬 568 · 일품 181 · 후식 141 · 밥 114 · 국·찌개 101 → **1,105** |
| METHOD | 끓이기 320 · 굽기 256 · 볶기 107 · 찌기 82 · 튀기기 70 → **835** |
| 합계 | **1,940행 / 레시피 1,114건** |

부여되지 않은 36건의 내역이 전부 설명된다.

- **8건** — 분류 줄이 없는 Flyway 시드
- **28건** — 양축 모두 '기타'

'기타'(조리법 307 · 음식형태 37)는 사전에 태그가 없어 미부여로 남는다. V14 설계 그대로다 —
뜻이 없는 값에 태그를 만들면 눌렀을 때 아무 공통점 없는 목록이 나온다.

배타축 위반(한 레시피에 같은 축 태그 둘)은 **0건**이다.

## 라벨이 한 군데 다르다

원문 `국&찌개` vs 사전 `국·찌개`. **사전 라벨을 원문에 맞추지 않고** 매핑에서 명시적으로 이었다 —
`label_ko` 는 화면에 나가는 값이라 원문 표기에 끌려다니면 안 된다. 이 매핑을 빠뜨리면 101행이
조용히 미부여로 남으므로 테스트로 고정했다.

## 검증

- 백엔드 전체 **200개 통과** (신규 7개)
- 신규 테스트는 **마이그레이션 파일을 클래스패스에서 읽어 그대로 실행한다.** SQL 을 테스트에
  옮겨 적으면 정작 배포되는 파일이 바뀌어도 통과해 버린다.
- 재실행 안전성(`ON CONFLICT DO NOTHING`)도 테스트로 덮었다.

## 이후 작업

- **문화권·용도는 이 방법으로 못 채운다.** 원문에 없어서 LLM 분류 말고는 길이 없다.
  용도 태그는 레시피오 조사(#87)로 사전이 먼저 넓어지는 중이다.
- **태그로 거르는 조회 API 가 아직 없다.** 부여가 채워져도 `GET /recipes?tags=…` 가 없으면
  홈 화면은 그대로다. 이게 다음 관문이다.
- `assigned_by='IMPORT'` 로 남겼다. 나중에 LLM 분류가 같은 축을 덮어쓰려 할 때 출처로 구분된다.
