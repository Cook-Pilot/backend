# LA갈비구이 단계 이미지 업스케일

## 무엇을 왜 바꿨는가

운영 레시피 `L.A 갈비구이`의 단계 이미지 6장은 너비가 모두 181px라,
조리 화면의 210px 높이 이미지 영역에서 확대될 때 재료와 조리 상태를 알아보기 어려웠다.
대표 이미지는 556×468px로 이번 교체 대상에서 제외했다.

GPT 이미지 편집으로 원본의 구도·재료·조리 상태를 보존하도록 복원한 뒤,
생성 원본을 1280px 너비·고품질 JPEG로 최적화해 운영 S3에 업로드하고
단계 URL만 교체한다.

## 핵심 결정

- 생성 유형은 `precise-object-edit`으로 제한했다.
- 단계별 재료 수, 용기, 배치, 액체 색과 양, 조리 상태를 불변 조건으로 프롬프트에 명시했다.
- 새 파일은 기존 파일을 덮어쓰지 않고 별도 S3 객체로 저장했다.
- 반복 가능 마이그레이션은 단계 ID, 레시피 ID, 기존 URL이 모두 일치할 때만 갱신한다.
  운영 데이터가 선행 변경된 경우 그 행을 덮어쓰지 않는다.
- 버전 번호를 사용하지 않아 병렬 개발 중인 `V12` 카탈로그 마이그레이션과 충돌하지 않는다.

## 스키마/API 변경

스키마와 API 계약 변경은 없다. `recipe_steps.image_url` 값 6개만 변경된다.

| 단계 | 원본 크기 | 교체 크기 |
| --- | --- | --- |
| 1 | 181×110 | 1280×779 |
| 2 | 181×109 | 1280×773 |
| 3 | 181×112 | 1280×791 |
| 4 | 181×106 | 1280×750 |
| 5 | 181×106 | 1280×751 |
| 6 | 181×106 | 1280×750 |

## 알려진 약점과 후속

- 181px 원본에서 보이지 않던 미세 질감은 생성 모델이 추정한 값이다.
- 운영 반영 후 실제 앱의 210px 높이 조리 화면에서 크롭과 로딩 속도를 확인해야 한다.
- S3 객체는 기존 리뷰 사진 업로드 경로를 재사용했다. 레시피 이미지 작업이 반복되면
  별도 `recipe-images/` prefix와 관리 업로드 경로를 추가하는 편이 낫다.
