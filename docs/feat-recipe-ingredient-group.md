# 재료 그룹 복원

## 배경

[재료 이름 오염 복구](fix-recipe-ingredient-names.md)에서 원문을 다시 파싱할 때
`주재료`/`양념장`/`소스`/`국물` 같은 **그룹 머리말을 정확히 뽑아냈지만 담을 컬럼이 없어
버렸다.** 나중에 재료를 분류할 때 필요하므로 되살린다.

원문에 있던 정보다. 임포터가 이 머리말을 재료 *이름*에 섞어 넣은 것이 이름 오염의 원인이었고,
이름을 정리하면서 머리말 자체가 사라졌다.

## 스키마

`V15__add_recipe_ingredient_group.sql` — `recipe_ingredients.ingredient_group TEXT` 추가.
`NULL`은 그룹 없음이고, 원문에 머리말이 없는 재료가 대부분이라 `NULL`이 정상 상태다.
`(recipe_id, ingredient_group)` 인덱스도 함께 만든다.

`ADD COLUMN IF NOT EXISTS`로 쓴 이유: 그룹 값 백필이 배포를 기다릴 수 없어서 운영 DB에는
유지보수 스크립트로 컬럼을 먼저 넣었다. 그래서 배포 때 이 마이그레이션은 운영에서 아무 일도
하지 않고 지나가고, 새로 만드는 환경에서는 컬럼을 만든다. 두 경로 모두 검증했다.

**애플리케이션은 아직 이 컬럼을 매핑하지 않는다.** `ddl-auto: validate`는 매핑되지 않은 컬럼을
문제 삼지 않으므로 앱은 영향받지 않는다(적용 후 API 응답 무변경을 1,150개 레시피로 확인).
조리 화면에서 그룹별로 묶어 보여주려면 엔티티·DTO·프론트 작업이 따라야 한다.

## 매칭 방법

추측하지 않는다. 두 경로로만 채우고 나머지는 `NULL`로 남긴다.

**A) 이름 복구로 재구성한 305개 레시피** — 그때 넣은 id가
`uuid5(uuid5(URL,'https://cookpilot.app/recipe-ingredient'), '<recipe_id>:<sort_order>:<name>')`
로 결정론적이라 다시 계산했다. 계산한 id 2,957개가 운영에 **하나도 빠짐없이 존재**하는 것을
확인해서, id 생성 규칙이 실제로 재현된다는 것까지 검증됐다.

**B) 그 밖의 레시피** — 원문 파싱 결과가 현재 행과 `(이름, 수량, 단위)` 순서까지 완전히
일치할 때만. 하나라도 어긋나면 그 레시피 전체를 건너뛴다.

| | 레시피 |
| --- | --- |
| A 재구성분 | 305 |
| B 완전일치 | 647 |
| 건너뜀 — 원문 없음(수동 시드) | 13 |
| 건너뜀 — 원문이 애매 | 113 |
| 건너뜀 — 정렬 불일치 | 72 |

결과: **952개 레시피 / 2,957개 재료 행**에 그룹이 붙었다.

## 그룹 값

원문 머리말을 그대로 넣었다. **163종.** 전체 목록은
`infra/maintenance/tools/ingredient-group-values.txt`에 있다.

```
  459  소스          197  양념장        69  필수재료
  351  재료          160  필수 재료     65  반죽재료
  315  주재료        153  육수          54  국물
  261  양념
```

`주재료`/`재료`, `필수 재료`/`필수재료`처럼 같은 뜻의 다른 표기가 섞여 있고,
`고추장소스`·`저나트륨된장소스`·`멸치견과류쌈장`처럼 레시피마다 다른 고유명도 있다.
**임의로 합치지 않았다** — 분류 체계를 세울 때 정할 몫이고, 원문을 보존하는 편이 되돌릴 수
있기 때문이다. 정규화 후보를 보려면 위 목록 파일을 쓰면 된다.

## 검증

운영에서 읽어온 1,150개 레시피 / 13,056개 재료 행을 로컬 PostgreSQL 17.6에 재현해 확인했다.

- 정상 경로: `UPDATE 2957` → 그룹 2,957행 / 163종
- V15 단독 실행(새 환경): 컬럼·인덱스 생성 확인
- V15 재실행(컬럼 있는 상태): `IF NOT EXISTS`로 무해하게 통과
- 재실행 가드: `ingredient_group 이 이미 2957행 채워져 있다`로 중단

리허설에서는 `ALTER TABLE`까지 함께 롤백되는 것을 확인했다.

## 남은 것

- **그룹 값 정규화** — 163종을 분류 체계로 정리하는 작업. 위 목록 파일이 출발점이다.
- **API·프론트 노출** — 엔티티에 필드를 추가하고 DTO에 실어야 조리 화면에서 그룹별로 묶인다.
- **그룹이 비어 있는 198개 레시피** — 113개는 원문이 애매하고(이름 복구에서도 보류한 것들),
  72개는 정렬이 어긋나 건너뛴 것이다. 후자는 이름 오염이 없어서 이름 복구 대상이 아니었지만
  파싱 결과와 행 구성이 달라 매칭을 포기한 경우다. 필요해지면 개별 확인이 필요하다.
